Authenticator demos

MAKOR (MakorX.AI) authentication design system

Two surfaces built from the HTML prototypes (there is no Figma): the web sign-in (light only; login → OTP → success; Geist + EB Garamond) and the mobile authenticator (390 x 844 phone mock; Geist only; light and dark as one system with a data-theme="dark" scope). All tokens are --mauth-*, all classes .mauth-web-* / .mauth-app-* / .mauth-icon, so nothing clashes with the main HR app system.

Reproduced exactly: every rendered colour, size, spacing, type, motion value. Documented, not reproduced: source bugs, dead code and external runtime dependencies (the Face ID dotLottie). Each demo shows its source file + lines, all variants/states through forced classes (.is-hover .is-focus .is-active .is-disabled .is-loading .is-error ...), and a Copy HTML button. Extended marks values that are not in the prototypes and were derived only from existing tokens.

Parts of this page

  • Foundations. Colours, type, radii, observed spacing, shadows, motion, sizes and icons, generated from tokens.json (mirrors tokens.css 1:1).
  • Components. Sixteen components: seven for the web sign-in, nine for the mobile authenticator. Authenticator demos have a Light / Dark / Both switch (they use the [data-theme="dark"] scope), the web ones are light only.
  • Screens. The flows re-assembled from the components at real size (web 460px card; phone 390 x 844, light and dark).
  • Reference. Known source bugs and decisions, dead code excluded, the index of Extended and Documented dependency items, open decisions for the owner.

Colours

Three families, all prefixed --mauth-. The web sign-in is light only. The mobile authenticator ships as ONE system: light values on :root, dark pairs under [data-theme="dark"]; each pair swatch shows light | dark side by side. Values are exact from the prototypes; near-equal colours stay separate (e.g. web-bg #C8D8DF and app-launch-bg #C8D8DF are two roles).

Typography

Geist everywhere. EB Garamond appears only in the web sign-in (titles, OTP digits, timer value, per the web spec). The authenticator has no serif: the source declares --font-serif but never loads or uses it. Radii

The auth UI is more rounded than the HR app (which uses 4px everywhere): web card 16, web field/button 8, OTP slot 12, app controls 4 (the sheet copy button is 8), shell min(44px, 4vw). Each radius is mapped to its element. The web 4px "focus-visible radius" is a source bug and is not reproduced.

Open decisions for the owner

Not decided by the owner yet; the system keeps what the prototypes render and flags it.

  1. Footer overlap on short viewports. The web page footer is position:fixed; z-index:2 and overlaps the card when the viewport is shorter than ~700px (observed at 559 x 597); at 375 wide each span wraps to 2 lines. Reproduced as rendered. Suggested: an in-flow footer below the card on short viewports. (S L63-73, L188; web-signin.md 4.23-24)
  2. White-on-teal and low-contrast text. White on the dark brand #17C3AF is ~2.2:1 (primary and copy buttons), white on dark danger #FF6B6B ~2.8:1 (danger confirm button, danger toast), web --mauth-web-text-3 #90AEBC on the card 2.09:1, app light --mauth-app-text-3 #A8B6CD on white ~2.05:1, white on web disabled #7FA0AB 2.79:1. Reproduced as designed; the owner decides whether to darken the fills or switch to dark labels. (authenticator.md 4.18; web-signin.md 1.1)
  3. Missing eye-off icon in the app. The password toggle in the authenticator never swaps its icon (only the eye glyph exists in the app; the web has eye-off). Decide: reuse web-icon-eye-off.svg for the app (then add .mauth-icon--app-eye-off) or keep a single icon and rely on aria-pressed. (A L366, L810-812)
  4. "Forgot password?" target. The link button has no handler and no destination; no forgot/reset screens exist. Rendered as designed (a link button); the product must define the flow. (S L376)
  5. Redirect target after success. After the 5 s countdown the page navigates to makor-dashboard.html, which does not exist (404). The DS documents a configurable target. (S L636)
  6. Copy for empty password and for clipboard failure. The authenticator shows "Enter your email and password." for an empty password (and for < 4 chars); the web shows "Incorrect credentials. Please try again." for a password shorter than 4 chars (no real credential check). Need distinct copy: a "please enter" message for empty fields and a server-rejection message. No copy exists for a clipboard failure (the source swallows the error in try/catch). (S L526-530; A copyCode (JS))
  7. Face ID failure / retry design. The animation never errors: there is no failure state, no retry limit, no lockout; the only exit besides success is "Use Passcode". A designer must supply the failure/retry visual (the Lottie cannot show one). (authenticator.md 2.3, 5)
  8. Lottie byte size and hosting. The file size of the dotLottie is not recorded; the animation and the player (@dotlottie/player-component@latest) are remote and unpinned. Decide: pin the player version and self-host a copy, or accept the dependency. (A L10, L689)
  9. BroadcastChannel name migration. Decided: makor_auth for web and app. The prototypes still use the legacy enigma_auth (S L537, L627; A L1230; D L1353-1360) and share the channel with the Enigma X prototypes. Prototype files must be changed together. (S L537/L627; A L1230)
  10. Brand spelling. "Makor-X.AI" (page title, app name), "Makor X.AI" (web sub copy) and "MakorX.AI" (brief) all appear. Copy is reproduced verbatim; the owner should choose one. (S L6 vs L346)
  11. Sheet / dialog dismissal and empty state. Esc, scrim tap and drag-to-close are missing for the sheet and dialog (decided as intended behaviour; JS only). The "No other active sessions." empty state exists in markup but is never shown (excluded; decide if wanted). (A L782; authenticator.md 4.8)
  12. Hub wiring. hub/projects.js and hub/ds-viewer.html resolve ../<platformId>/design-system/tokens.json; this system lives in makorx-ai/auth-design-system/. Wiring is outside the design-system stages. (build-notes.md 7)
