# Reconciliation — existing `makorx-ai/design-system/` vs the built app `makor-hr/employees.html`

Source of truth: `makor-hr/employees.html` (CSS lines 10-1720, dark block 1046-1719; JS 3506+). Figma ignored (owner).
Compared: `design-system/{CLAUDE.md, tokens.css, tokens.json, components.css, components.md, showcase.html}`.

Method: (1) read every rule of app CSS and `components.css`; (2) computed-style harness in an own browser tab, transitions disabled (`*{transition:none!important}` injected, because a background tab does not advance transitions), 70 matched (app selector, showcase selector) pairs, light AND `body.dark`, 24 properties each; (3) class-name set diff (app CSS 620 classes, DS `components.css` 264, overlap 74); (4) script scan for classes with light colour literals but no `body.dark` rule.
Env note: DPR 1.5, so computed `border-width: 1px` reads `0.666667px` and `1.5px` reads `1.33333px`; authored values below are quoted from CSS. Items marked "(computed)" are browser-only.
Headline: **the first ~22 components of `components.css` (lines 1-1075) reproduce the app very closely (0 colour diffs in light or dark for buttons, inputs, search, select, status pill, dept badge, tabs, modal, toggle, toast, datepicker, table). Everything from `/* EXTENDED COMPONENT LIBRARY */` (line 1076) onward is NOT in the app.** The class names differ from the app in many places (the DS renamed them), so DS CSS cannot be dropped onto the app and vice versa.

## 1. Sidebar question (settled)

- **The app has NO left sidebar anywhere.** Only a fixed top nav `.top-nav` (line 17: `position:fixed; top:0; left:0; right:0; height:74px; background:#fff; padding:0 40px; z-index:100; border-bottom:1px solid #e5e7ec`). A scan of every `position:fixed|sticky` element (computed) found only: `.top-nav`, `.save-bar` (sticky), table `th` (sticky), `.left-col` (sticky, My Profile), overlays/dropdowns.
- Closest thing: **My Profile `.left-col`** (line 497: `width:360px; position:sticky; top:90px; display:flex; flex-direction:column; gap:12px`) containing white cards `.sidebar` (line 499) and `.reminders-card` (500). Colours (computed): light `.sidebar` bg `#ffffff`, border `#e5e7ec`, shadow `0 2px 8px rgba(0,0,0,0.06)`, radius 4px, padding `18px 16px`; dark `.sidebar` bg `#202226`, border `rgba(255,255,255,0.07)`, shadow `none` (line 1545). Page behind it: `#myprofile-view{background:#f5f5f8}` (line 1025) / dark `#111214` (1083). `.sidebar-profile` block inside: light `#f5f5f8`, dark `rgba(255,255,255,0.04)`.
- Therefore three-way contradiction in the existing DS, all wrong vs app: `CLAUDE.md:49` says "Raised `#f5f5f8` ... sidebar"; `components.css:1963-1976` `.sidebar{width:220px; height:100vh; background:#111214 ...}` (dark in LIGHT mode too, border `rgba(255,255,255,0.07)`), with `.sidebar.light` variant `#fff` (line 2094) — never `#f5f5f8`; `showcase.html:232` `.demo-sidebar-frame .sidebar`. **Verdict: sidebar nav = NOT IN APP (invented). Also a class-name COLLISION: app `.sidebar` = white 360px profile card; DS `.sidebar` = 220px fixed dark nav shell.** Settle: if the owner wants a sidebar it is an EXTENDED component; the neutral choice consistent with app surfaces would be `.sidebar.light` (`#fff`, border `#e5e7ec`), not `#f5f5f8` and not `#111214`.

## 4. Dark-mode completeness

Method: script scan of every class that carries a light colour literal and has no `body.dark` selector.

**App (`employees.html`)** — 18 classes without a dark rule; real gaps (computed/CSS):
- `.tt-fillall-overlay` (360) and `.tt-confirm-overlay` (375): backdrop stays `rgba(0,0,0,0.28)` in dark (other overlays go 0.55-0.65).
- `.req-select-to` (936): `background-color:#fff; border:1px solid #e5e7ec; color:#1a1a1a` — dead CSS (0 HTML/JS uses) so harmless.
- `.req-date-native`/`.has-date` (943-944): `#a8b6cd` / `#1a1a1a` with no dark rule (2-3 JS uses) — covered only by the generic `[style*="color:#a8b6cd"]` attribute overrides if inline, else gap.
- `.nav-sub` (23): stays `#7c8dac` in dark (readable, undocumented).
- `.btn-save-bar`/`.btn-discard-bar`/`.dm-thumb`/`.ev-avatar`/`.req-star`/focus-within rules: intentional (sit on brand bar / fixed colours).
- Inline-style fallbacks: `body.dark [style*="color:#7c8dac|#a8b6cd|#b0b8c8|#c4cdd9|#c4cdd8"]` and 3 pastel `[style*="background:..."]` (1703-1711) — a patch layer; any new inline colour not in that list will not flip.
- `body.dark .phone-flag,.phone-code-val{...}` (1608) has a selector-list bug (second selector lacks `body.dark`, so `.phone-code-val` is `#e2e8f4` in light mode too, computed not re-verified).
- 3 dark-only inconsistencies: table header bg is `#111214` for `.emp-table`/`.records-table`/`.section-band`/`.group-header-row`, but `#202226` for `.rv-table`/`.tt-table`/`.req-table`/`.hist-table`/`.tt-cal-head`/`.wfh-cal-head`.

**DS `components.css`** — dark rules exist for every core component. Missing dark overrides (script): `.search-icon` (stays `#a8b6cd`, app `#505a6c`), `.data-table tr.row-new` (app dark `rgba(12,184,208,0.06)`, 1344), `.daterange-sep`, `.confirm-overlay` (0.36 both modes), `.spinner-white`, `.tag-input-wrap:focus-within`; sidebar is dark by default, its `.light` variant has no dark.
