Enigma X auth design system

Web sign-in portal (login, two-factor code, success) and the mobile Authenticator (launch, Face ID, devices, push banner, sign-in sheet, password fallback). Light only. Tokens --eauth-*, classes .web-* / .app-*, icons .eauth-icon. Values present in the prototypes are reproduced exactly; anything the source is silent on carries the Extended badge; the Face ID animation is a Documented dependency, shown as a labelled placeholder only.

Badge legend

Extended
Not drawn in the source; built from existing tokens.
Alt
Alternate treatment present in the source next to the canonical one.
Documented dependency
External runtime dependency (remote animation, font, API): documented, not copied.
Outside canonical
Drawn in the source but outside the canonical section or page.

Every demo has a source line (file + lines), forced state classes (.is-hover .is-focus .is-active .is-disabled plus the JS state classes) and Copy HTML. Showcase wrappers (card padding, phone crops) are not part of the system.

Components are grouped by role: Actions (buttons) · Forms & inputs (inputs, OTP slots) · Selection controls (checkbox) · Feedback (timer / resend, states, toasts) · Overlays (confirm dialog) · Platform patterns (web card and logo, phone frame, launch, Face ID, home and session cards, push banner, bottom sheet, password fallback). The two flows are under Screens. Counts: assets is the number of distinct files in assets/ (23); the page renders them 47 times.

Colours

Every colour in the two prototypes, split per surface. Hover teal #5ADADA is the only hover colour in either prototype (#3DBFBF is chrome, not hover).

Mask icon recipe Recipe

Monochrome icons: <span class="eauth-icon eauth-i-NAME"></span>. .eauth-icon is background-color: currentColor + mask: url(assets/…) center / contain no-repeat (with -webkit-); the size is set by the component (the icon has no intrinsic size). Never redraw or hand-write icon paths. The Enigma mark is one class .eauth-i-logo because the web and app path data are byte-identical: web 72px #7AEFEF, launch 108px #3DBFBF, white on the home tile (30px) and push tile (22px). There is no eye-off icon in the app, no close icon, no icon set beyond these.

Old docs that drifted from the prototypes (do not repeat)

  • Top navigation bar (56px, frosted), "Waiting badge", "Secured by 256-bit TLS" badge and "OR" divider as live web components: none has markup; CSS only (dead).
  • Avatar / initials circle and a "session-current" card as live mobile components: the CSS exists, nothing renders it.
  • "Border radius always 4px": the web card, OTP slots and app cards/code card/copy button are 8px; dialog 14px; banner 22px; icon tiles 10/12px.
  • "#3DBFBF is the mobile hover colour": the only mobile hover is #5ADADA (.btn-primary:hover, hard-coded). #3DBFBF is chrome (banner, status bar, eyebrow, push tile, focus outline).

Open decisions for the owner

Not resolved by the source. The system documents them; none is invented.

  1. Empty-password error copy. The source shows "Incorrect credentials. Please try again." for a short password (bug W2). Which copy should an empty/short password show (e.g. "Enter your password.")?
  2. Expired-code label. Web timer at 0: proposed "Code expired" (replaces the whole label, bug W6). Confirm the copy.
  3. Clipboard-failure message. Authenticator copy button when the Clipboard API rejects (bug A2): toast copy not designed (e.g. "Couldn't copy. Select the code and copy it manually.").
  4. Target of "Forgot password?". No handler or destination exists (bug W10).
  5. Post-login redirect target. Success redirects to enigma-dashboard.html, which does not exist (bug W9). 5s countdown kept.
  6. Face ID failure / retry. No failure, retry, lockout or "biometric unavailable" design exists; tap-to-retry is unreachable in source (bug A3). Design needed.
  7. Eye-off icon for the app. The app password toggle never changes its icon; no eye-off asset exists in the app (the web has web-icon-eye-hide.svg). Reuse the web asset or draw a new one?
  8. DM Mono 600 (synthetic bold). OTP digits, timer, status time, OTP code and countdown declare 600 on a font that only has 500 loaded. Keep the synthetic bold (as rendered) or switch to 500?
  9. App input double focus ring. Border + 4px ring + 2px #3DBFBF outline (bug A7). Keep or remove the outline like the web?
  10. Cross-system font note. Enigma main trading app (Figma) uses Geist / Geist Mono with the same brand #7AEFEF; auth keeps DM Sans / DM Mono (owner decision 2026-10-14). Recorded, not unified.
  11. Shared BroadcastChannel name. Confirm the per-product channel name "enigma_x_auth" (bug X1) and that Makor gets its own.
  12. Showcase kit: Copy HTML fidelity (decision M6). The kit copies template.innerHTML, so the card-level button writes boolean attributes as checked="" / disabled="" (9 cards, 18 of the 104 sources); the per-state and per-screen buttons copy the source text verbatim. Accept this, or extend the kit to copy the template text as written?
  13. Showcase: checkbox placement (decision M7). The checkbox card now sits under Selection controls instead of Inputs, following the role grouping in the kit structure. Confirm, or move it back under Forms & inputs.
  14. Showcase: chrome accent colour. The kit accent and the Extended / Outside badge colours are derived with color-mix() from --eauth-brand-chrome and --eauth-web-text because #3DBFBF on white is too light for links and badge text (the system has no darker teal token). Confirm, or supply a token.
